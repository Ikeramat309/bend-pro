# Build a Run - open questions

## Architecture blockers

1. Shared child-result contract: marks, origins, references, extents, warnings, plane, and engine version.
2. Anchor semantics for each calculator family.
3. Migration policy when calculator math/profile data changes.
4. Which child types expose validated developed-length effects in Phase B.

## Product questions

1. Final name: `Build a Run`, `Run Layout`, or `Stick Plan`.
2. How users confirm bend order without turning the screen into CAD.
3. Whether a formed-run preview adds trust or creates false precision.
4. Whether manual marks belong in the main flow or an Advanced tool.
5. How to communicate `coordinate fit` versus `fully validated cut length`.

## Deferred

- Automatic optimal bend order
- Arbitrary 3D routing/CAD
- Mixed conduit material rules
- Universal CLR/gain chaining
